### Lab0.zip

Puran lab0.zip-tiedoston 

![]()

Käännän buggy_program.c binääriksi käyttäen gcc:tä. Lisään myös -g, -Wall ja -Werror valitsimet. 

-g mahdollistaa GDB:n käytön

-Wall varoittaa, jos loogisia ongelmia ensiintyy

-Werrer muuttaa varoitukset kriittisiksi varoituksiksi ja keskeyttää käännön

```
gcc -g -Wall -Werror buggy_program.c -o lab0
```

Suoritan ohjelmaa debuggerin kanssa ja käytän layout split komentoa 

```
gdb ./lab0
layout split
```

Tästä näen lähdekoodin ja debugger konsolin.

![]()

lähdekoodissa lukee vihjeenä  ```for(int i=0; i<= size; i++)``` aiheuttaa ylipuskurivuodon ja ```buggy_function(numbers, 5);``` antaa virheellisen koon

suoritan ohjelman ```run```-komennolla ja huomaan, että ohjelma listaa numbers[]-taulukon sisällä olevien numeroiden lisäksi ylimääräisen luvun.

![]()

Suuntaan lähdekoodiin poistumalla debuggerista ```exit```-komennolla ja muutan buggy_program.c for-silmukssa ```i<= size``` ==> ```i<size```, koska silmukka muuten jatkaa kunnes sizes on yhtäsuuri
kuin 0, jolloin ohjelma antaisi viiden sijaan 6 vastausta. 
![]()

Tallennan ja kompiloin ohjelman uudelleen ja suoritan ohjelman 

```
gcc -g -Wall -Werror buggy_program.c -o lab0
./lab0
```
![]() 

Nyt ohjelma tulostaa vain taulukon viisi lukua.

### Lab1.zip

Puran ja kompiloin lab1.zip
```
unzip lab1.zip
cd lab1
gcc -g -Wall -Werror gdb_example1.c -o lab1
```

ajan ohjelmaa käyttäen debuggeria ja annan layout split-komennon, jotta voin tarkastella myös lähdekoodia

```
gdb ./lab1
layout split
```

![]()

laitan break-komennon main-funktioon ja suoritan ohjelmaa. Ohjelma pysähtyy main funktioon.

```
b main
r
```
Haluan tarkastella bad_message ja good_message arvoja, joten käytän ```watch```-komentoa.

```
watch bad_message
watch good_message
```

![]()

jatkan ohjelman suorittamista ```c```-komennolla.  Huomaan, että good_message saa uuden arvon ja bad_message saa arvon ```0x0```.  

![]()

Ohjelma lopettaa antamalla vastaukseksi ```Khoor/#zruog1```

![]()

Tarkastelen lähdekoodia ja huomaan, että ohjelma salaa jokaisen message merkkien ASCII-arvot lisäämällä i yhtälön ASCII-arvon käyttämällä ```do-while```-silmukkaa. Veikkaan, että muuttamalla i-yhtälön 
arvoa nollaksi salaus ei enään toimi.

Käyn microssa muuttamaan i:n arvon nollaksi
```

micro gdb_example1.c

![]()

Kompiloin ja suoritan ohjelman uudelleen

```

![]()

### passtr2o

ajan ohjelmaa debuggerissa 

```
gdb ./passtr2o
layout split
```

Nyt ei nähdä lähdekoodia, joten täytyy etsia salasana ja lippu käyttämällä pelkästään debuggerin komentoja

Vertaan passtr-ohjelman assemble käskyihin, huomaan, että passtr2o:n  main-funktiossa ei löydy call strcmp@plt-käskyä, vaikka molemmat ohjelmat näyttäisivät olevan toiminnoiltaan samoja. passtr2o 
luultavasti tekee strcmp- käskyn toisessa funktiossa. 

![]()

Määritän breakpointit mAsdf3a ja EaseEAs, koska haluan tarkastella näitä funktiota.

```
b main
b mAsdf3a
b EaseEAs
```
suoritan ohjelman käyttämällä ```r```-käskyä ja etenen ```s````-käskyllä. Annan satunnaisen salasanan, jonka jälkeen päädyn mAsdf3a funktioon.

Tässä kohtaa jäin jumiin, enkä osannut edetä pidemmälle, joten kysyin tekoälyltä vinkkejä. 

![]()

Siirryn eteenpäin ```s``` ja päädyn takaisin main-funktioon Lea-käskyn kohdalle. Lea-käskystä näen %rsp ja %rdi, nämä ovat suorittimen rekistereitä. Tarkastelen näitä rekistereitä komennoilla: 

```
x/s $rsp
x/s $rdi
```
Huomaan, että rdi on antamani salasana ja rsp on luultavasti oikea salasana

![]()


Etenen käsky käskyltä ``` ni```-käskyllä, kunnes olen jne-käskyn kohdassa. Tässä on if-silmukka, joka käy edellisen dec-käskyn läpi ja käy lea-käskyn tuomat merkkijonot läpi, joten haluan saada siitä TRUE tai arvon 1.
Saan sen antamalla ```set $eflags|=(1<<6)```-käskyn, mikä asettaa lipun arvoksi 1. 

![]()

Etenen eteenpäin ```s```-käskyllä kunnes suoritan ohjelman loppuun. Koska ohjelmaa huijattiin if-silmukassa hyväksymään antamani salasana oikeaksi ohjelma antaa lipun 

![]()

### crackme

Valitsen tehtäväksi crackme01.64.

Avaan tehtävän debuggerissa ja laitan breakpointiksi main-funktion

```
gdb ./crackme01.64
layout split
b main
r
```
Huomaan assemblerista samanlaisen call strncmp@plt-käskyn kuin passtr-ohjelmassa, jossa hypätään toiseen funktioon ja verrataan merkkijonoja. 

Kokeilen ensin käymällä ohjelman läpi ```ni```-käskyllä.

Huomaan, että kohdassa main+9 on if-silmukka, joka hyppää call strncmp-käskyn yli, jos arvo ei ole 0. 

![]()

Samoin tavoin kuin passtr2o tehtävässä annan if-silmukan lipulle arvon 1.
```
set $eflags|=(1<<6)
```
Jatkan ```ni```-komennolla, kunnes pääsen call strncmp@plt-käskystä toiseen funktioon.

![]()

Tarkastelen rekistereitä %rdi,%rsi ja %rdx

```
x/s $rdi
x/s $rsi
x/s $rdx
```

![]()

Nähdään, että salasana on password1. 

Kokeilen toimiiko salasana
